* Versions: revised since the conference version
* Conference version (36d156218)

*If* you want the agent to discount low-trust evidence without discarding it, and to become stricter when outcomes are volatile. *However* without an explicit precision layer, evidence weighting becomes implicit prompt rhetoric and cannot be audited. *Then* keep a per-channel /precision registry/ --- one trust weight per kind of evidence --- keyed to observation features, and apply it wherever prediction error, scoring, or gating occurs. *Because* making precision explicit turns trust into a tunable control surface rather than an undocumented bias.

The registry exists: one precision state per observation channel that has a likelihood model, each carrying its precision and a bounded error history, updated from that channel's prediction errors (see R3 for the floor and cap). It is maintained in the War Machine report's inner judgement loop (war_machine.clj), stepped alongside the belief. Volatile outcomes raise the error variance and so lower precision, which is the 'stricter when outcomes are volatile' of the If. The current text's worknote cites ten admitted precision claims; not re-checked.

- Ticket: paper edit candidate: R7's Then should name the distinct precisions (per-channel evidence precision, likelihood precision zeta, policy/reading precision beta) and where each is applied, instead of one registry applied everywhere

The live cascade path does not consult this registry. It uses two other precisions, each declared separately: likelihood precision zeta (likelihood_precision.clj), a fixed declared inverse temperature on A, which on the identity-kernel path multiplies nothing and is declared FIXED-VACUOUS there; and the reading-policy precision beta (reading_policy_precision.clj), set to 1 by a sealed operator declaration for the readiness campaigns. So precision is explicit and auditable, which is the pattern's Because, but it is not one registry applied everywhere. Having several distinct precisions (likelihood, policy, evidence channel) is standard in active inference, so by the revision policy this is a docs discrepancy: the code is AIF-valid and the text should describe the three precisions and where each applies.
