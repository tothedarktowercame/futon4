* Versions: revised since the conference version
* Conference version (36d156218)

*If* an instrument issues a verdict from evidence it also produces or stages (a calibrator over its own predictions, a gate over its own outputs). *However* on first contact with reality every layer tries to certify /itself/, and each attempt looks rigorous --- the forward model scores its own constants ("prior \(=\) value"), the evidence reader eats its own staging files --- and vigilance cannot catch these, because an instrument's first catches are always about itself. *Then* require that a verdict move /only/ on evidence its maker did not manufacture: tag every evidence record at birth with properties the apparatus cannot fake (=:independent?=, =:measured= vs =:target-absent-fallback=, =:settled= vs =:transient=) and count only records whose tags clear --- untagged never counts. *Because* circularity is invisible from inside the loop (every internal reading is consistent with every other); only a referent the maker had no hand in breaks it, and structure ("the tag is absent, so it does not count") survives where vigilance fails. /Revised against the record:/ the rule reached one layer further than first written --- =:review-execution-evidence-missing=, twice in the first cohort: a /review/ is itself a verdict-producing act, and a reviewer's claim that a review ran is exactly the kind of self-manufactured evidence the pattern bars. The landed revision corroborates review execution from the job-event stream the reviewer does not control, before any review counts.

* Current version (96ab1a056)

*If* an instrument issues a verdict from evidence it also produces or stages (a calibrator over its own predictions, a gate over its own outputs). *However* on first contact with reality every layer tries to certify /itself/, and each attempt looks rigorous --- the forward model scores its own constants ("prior \(=\) value"), the evidence reader eats its own staging files --- and vigilance cannot catch these, because an instrument's first catches are always about itself. *Then* require that a verdict move /only/ on evidence its maker did not manufacture: tag every evidence record at birth with properties the apparatus cannot fake (=:independent?=, =:measured= vs =:target-absent-fallback=, =:settled= vs =:transient=) and count only records whose tags clear --- untagged never counts. The rule covers verdicts about verdicts: a review is itself a verdict-producing act, and a reviewer's claim that a review ran is exactly the kind of self-manufactured evidence the pattern bars (measured as =:review-execution-evidence-missing=, twice in the first cohort), so review execution is corroborated from a job-event stream the reviewer does not control before any review counts. *Because* circularity is invisible from inside the loop (every internal reading is consistent with every other); only a referent the maker had no hand in breaks it, and structure ("the tag is absent, so it does not count") survives where vigilance fails. /Scope in this implementation:/ the universal birth-tag regime is the invariant a conforming implementation must keep, not a description of this one. The running stack has birth tags on the rollout/flight paths and review-execution corroboration conditional on changed code files; it has no catalogue-wide structure that tags every evidence record or excludes every untagged record. Those narrower mechanisms are evidence of partial application only.

That code is from the pilot era (last changed 2026-06-12) and serves the futon3c pilot and flight-record paths; the futon2 full-loop runner does not consult it. Read as a description of this implementation, the conference text's 'every evidence record' and 'untagged never counts' overclaim. Execution evidence comes from outside the reviewer: Agency derives the job's :execution summary by counting tool-use events in the seat's own event stream (http.clj), and the runner also counts those events directly from the job record. But review-execution-gate requires execution only when the reviewed files include code (required? is true only if a file matches the code-file pattern); a review of data or prose files passes without it. So 'before any review counts' does not hold. The public independent-review-evidence validator does always require execution. The current text's 'conditional on changed code files' is accurate.
